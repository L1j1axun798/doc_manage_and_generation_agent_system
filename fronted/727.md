1. 前端是否根据当前选中的项目请求对应资料。
2. 后端接口是否接收项目 ID 并按项目过滤文件。
3. 文件与项目之间是否存在正确的数据关联。
4. 接口权限是否导致资料无法返回。

修改后的业务逻辑为：

   `<span>当前项目暂无入场前置资料，请先前往资料中心上传。</span>`

## 四、问题三：“入场前置资料”的目录和页面结构

将资料中心原有的一级目录“竣工资料档案”调整为“入场前置资料”。

注意：这是对单个一级目录的更名和业务调整，不是删除资料中心的全部目录后重新创建。

“入场前置资料”页面可参考现有“公司资质”页面的布局、交互和权限控制，但资料需要按照项目进行分类存储。

页面结构：

```
资料中心
└── 入场前置资料
    ├── 项目 A
    │   ├── 文件 1
    │   └── 文件 2
    ├── 项目 B
    │   ├── 文件 1
    │   └── 文件 2
    └── 项目 C
```

具体要求：

1. “入场前置资料”根目录下，每一项代表一个已存在的项目。
2. 项目目录名称展示项目正式名称，必要时附带项目编号。
3. 点击项目后，进入该项目的入场前置资料页面。
4. 页面展示该项目已经上传的前置资料。
5. 上传资料时，文件必须与当前项目建立明确关联。
6. 用户不得在“入场前置资料”根目录下随意创建与项目无关的一级文件夹。
7. 项目目录应基于项目数据生成，不应通过普通文件夹名称模拟项目关系。
8. 项目新增、修改名称或停用后，入场前置资料页面应根据现有项目数据正确更新，避免产生重复项目目录或孤立目录。
9. 页面布局和文件操作可复用“公司资质”页面，但不得影响“公司资质”原有功能。

## 五、入场前置资料与项目管理的同步规则

“入场前置资料”和“项目管理”之间采用单向同步关系。

### 允许的同步方向

```
资料中心 / 入场前置资料 / 对应项目
                    ↓
项目管理 / 对应项目
```

在“入场前置资料”中上传的文件，应同步显示到“项目管理”中对应项目的文件列表里。

### 禁止的同步方向

```
项目管理 / 对应项目
          ✕
资料中心 / 入场前置资料 / 对应项目
```

在“项目管理”对应项目中直接上传的普通项目文件，不得自动同步到“入场前置资料”。

实现时应注意：

1. 不建议创建两份完全独立的物理文件副本。
2. 优先采用同一文件记录或统一文件实体，通过来源类型、业务分类或关联表控制文件在哪些页面展示。
3. 入场前置资料上传的文件，应同时满足：
   * 关联当前项目；
   * 标记为“入场前置资料”；
   * 可在项目管理对应项目中查看。
4. 项目管理中普通上传的文件，应满足：
   * 关联当前项目；
   * 不标记为“入场前置资料”；
   * 只在项目管理中展示。
5. 删除、移动、重命名文件时，应基于同一文件实体保持数据一致，避免出现一个页面已删除、另一个页面仍存在的情况。
6. 必须避免循环同步、重复记录和重复文件。

可参考以下逻辑设计：

```
文件关联项目 + 文件来源类型/业务分类

source_type = entrance_material
    → 入场前置资料页面可见
    → 项目管理页面可见

source_type = project_upload
    → 项目管理页面可见
    → 入场前置资料页面不可见
```

字段名称可根据现有模型设计确定，不要求机械使用 `<span>source_type</span>`，但必须实现同等业务语义。

## 六、四措两案编制任务与资料的关联

创建编制任务时：

1. 用户必须先选择项目。
2. “已有项目资料”仅查询当前项目中标记为“入场前置资料”的文件。
3. 用户可以多选这些文件作为本次四措两案编制任务的输入资料。
4. 保存任务时，应保存任务与所选文件之间的关联关系。
5. 后续查看任务详情、执行 Agent 或重新编辑任务时，应能够恢复已选资料。
6. 后端必须校验所选文件是否：
   * 属于当前项目；
   * 属于入场前置资料；
   * 当前用户具有访问权限。
7. 不得仅依赖前端过滤，防止通过修改请求参数关联其他项目文件。
